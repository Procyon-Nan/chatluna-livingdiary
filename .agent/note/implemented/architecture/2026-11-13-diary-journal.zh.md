# Agent Note: 日记历史与写作素材

Status: implemented

## 问题

日记写成后，即使没发到 QQ 空间也有保留价值。靠调试日志和空间动态，无法稳定查到写过的日记、写作时有哪些记忆可用，也无法在记忆后来被编辑时还原素材。

## 决策

每篇日记生成后先写入实例数据库，再提交到 QQ。保存预设、日记日期、写作时间、完整正文，以及实际交给模型的全部记忆 ID 和当时的原文，保留原顺序。同一天再写一篇也单独保存；没有生成正文的运行不建档。

空间发布结果单独记录。仅保存、尚未尝试发布的日记为「未发布」。每篇只发一次，按回执中的动态 ID 读到原帖才算「已发布」；列表里正文相同的动态无法证明是这次发布的。其他已尝试的结果都记为「发布失败」。控制台按预设翻阅日记，选中日记后在右页读取并展示素材；插件设置使用框架的配置编辑器。

## 考虑过的替代方案

只存记忆 ID 会让旧日记的素材随 LivingMemory 中的编辑和删除而变。让模型标明引用则回答了另一个问题：日记本记录的是写作时给了它什么，不要求它说明正文采用了哪些句子。

## 影响

每篇日记会多占用一份有限数量的记忆文本。即使来源被修改、插件重启或发往空间失败，用户仍能查阅当时的素材。
