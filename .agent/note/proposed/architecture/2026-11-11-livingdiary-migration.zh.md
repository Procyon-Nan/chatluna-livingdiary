# Agent Note: LivingDiary 迁移至 ChatLuna v2

Status: proposed

## 问题

LivingDiary 会向真实 QQ 空间发帖。v2 工具调用可以指定同轮另一名发言人，但在群里说过话不等于授权别人发帖。v1 另有两处实现偏离原意：SDK 没有收到通过登录信息补出的账号，每日日记也只读了第一页记忆。

## 提案

`qzone_publish` 按实际请求者授权。其他发言人不能出借身份或白名单权限。无法确定请求者或请求者不在白名单时，不执行写入。这条规则适用于对话内发帖；定时日记和自动互动保留各自的入口。

创建 SDK 客户端和续绑会话时，均传入 Cookie 和已解析的账号。每日日记读取指定预设从本地零点到本次任务开始时创建的活跃记忆，按创建时间取最近的配置条数，再从早到晚交给模型。

每个插件实例选一个空间预设。每日日记读取该预设的记忆，以它的口吻写作；自动评论和回复沿用同一人设。日记和自动互动可以分别选择模型。对话内调用 `qzone_publish` 时，当前对话提交的正文走原有发布流程，不再调用模型按空间人设改写。

## 考虑过的替代方案

**按被点名的发言人授权。** 只要 Alice 在同轮发过言，Bob 就能借她的权限发帖。

**照搬 v1 的调用。** 即使适配器已经查到账号，缺少账号字段的有效票据仍可能无法建立会话。只取按更新时间排序的第一页，会让今天编辑的旧记忆挤掉今天的新记忆。

## 验收条件

白名单里只有 Alice 时，Alice 请求可以发帖。即使两人在同轮都发过言，Bob 也不能以 Alice 的名义发布。无法识别请求者时写入次数为零。用模拟 SDK 核对实际写入次数。

使用未携带账号的票据，由适配器补出账号；验证 SDK 在创建客户端和续绑时均收到该账号。

将日记上限设为 100，准备超过 100 条当天新建的活跃记忆，混入归档记忆及今天编辑的旧记忆。无论如何分页，模型只收到符合条件的最近 100 条，按创建时间正序排列。

插件选择预设 A，群聊使用预设 B：每日日记取 A 的记忆并以 A 的口吻写作；自动回复使用互动模型和 A 的人设；群聊内调用发布工具时，使用对话提交的正文，不额外调用模型。

## 风险

框架可在处理代发参数后才确定工具的执行身份。集成测试须区分原请求者和替换后的身份。SDK 与日记用例均可在不向 QQ 发帖的情况下验证。

同一群聊切换请求者的验证结果：白名单用户用过工具后，框架缓存的模型请求中可能保留工具名和参数说明；下一轮请求者未获授权时，当前工具目录中没有该工具，实际调用也会被拒绝。

## 迁移进度

- [x] 空间命令和对话发帖：插件构建通过；使用模拟发布端验证请求者白名单和实际写入次数；通过本地配置的 OneBot 账号真实读取一条自己的动态。Milky 已有适配测试，待真机联调。
- [ ] 每日日记：迁移手动执行、定时运行、预设渲染与当天记忆筛选。
- [ ] 自动互动：迁移轮询、评论线程筛选、媒体读取及任务取消。
